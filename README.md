# Umit Bozdag — personal website

The website of Umit Bozdag, Senior Operations Manager (exhibitions & events, London).
Node.js + Express + EJS, vanilla CSS/JS, no build step. White, blue and black editorial theme with a London
hyperlapse under the name, event logos and show imagery, one page per show, a Tube-style career line,
a world map, a contact form, a WhatsApp button and a server-side visitor log with an admin dashboard.

## Run it

```bash
npm install
npm start          # http://localhost:3000
npm run dev        # same, restarts on file changes (Node 18+)
PORT=8080 npm start
```

## Edit the content

The home page is deliberately simple: a London film under the name, a world-map strip, **About** (intro, facts, where I've worked),
**What I do** (six service cards), **Events** (every show, filterable by organiser, with the world
map) and **Contact**. Everything shown lives in **`data/profile.js`** — name, title, `statement`,
`intro` paragraphs, `facts`, `stats`, `employers`, `servicesIntro` + `services`, `alsoSkills`, the
`shows` (each with its own page), `experience` (used on the show pages), map `cities` and contact
links. Edit that file and restart; no HTML changes are needed.

- **Press coverage:** a show can carry a `press` list — `{ title, source, date, url }` objects — shown on its
  page as **"In the press"** (external links, newest first as entered) and as a small "In the press" marker in
  the home-page list. In the admin it is one line per article: `Headline | Publication | 2015-09-10 | https://…`.
  Links must be absolute web addresses; the date can be `YYYY`, `YYYY-MM` or `YYYY-MM-DD`.
- **Shows:** each entry in `shows` has an `id` (its page is `/shows/<id>`), `logo` (see below), `url`
  (the event website, linked from the card and the page), `image`, `venue`/`city`/`country`,
  `years` or `dates`, a `summary`, `responsibilities` and optional `highlights`. `featured: true` puts
  it in the large cards at the top of the Shows section.
- **Event / employer logos:** drop a file named after the `logo` slug into `public/img/logos/`
  (`.svg`, `.png`, `.webp` or `.jpg`, e.g. `logo: 'gastech'` → `public/img/logos/gastech.webp`).
  The server picks it up on start; anything without a file shows a text wordmark instead
  (currently only Taste of London). Logos belong to their respective organisers and are shown here
  only to identify the events Umit has worked on.
- **Contact details:** `email` is used everywhere; `whatsapp` (digits only, with the country code,
  e.g. `447704050921`) powers the floating WhatsApp button and the WhatsApp links, and
  `whatsappText` pre-fills the first message. The phone number itself is never printed — the `phone`
  line stays commented out.

- **Your own photos:** drop files in `public/img/` and point any `image` field at them
  (e.g. `image: '/img/gastech-2025.jpg'`). The illustrated scenes under `public/img/scenes/` are
  placeholders generated by `npm run build:media` (needs Playwright) — replace them with real show
  photos whenever you like.
- **Testimonials:** add entries to `testimonials` and the section appears automatically.
- Map cities need `lat`/`lon`; the one marked `hq: true` is the origin of the animated routes.
- Styling lives in `public/css/style.css`, behaviour in `public/js/main.js`, the illustrated London
  renderer in `public/js/london-scene.js`, markup in `views/index.ejs`.

## Header video

The hero plays the free Pexels clip **“Aerial View of a City”**
(https://www.pexels.com/video/aerial-view-of-a-city-6099374/ — Pexels licence, free to use).
`heroVideo` in `data/profile.js` lists three sizes; the browser picks 540p on phones, 720p on laptops
and 1080p on large/high-DPI screens. While it loads (or if it cannot load) an animated illustrated
London skyline plays behind the name instead.

- **Self-host the file (recommended for Hostinger):** `npm run fetch:video` downloads it to
  `public/video/london.mp4`; when that file exists the server serves it instead of the Pexels CDN.
  `npm run fetch:video -- desktop` fetches the smaller 720p file.
- **Different clip:** change the `sources` URLs (or just drop any `public/video/london.mp4` in place).
- **Look:** `tone: 'duotone'` applies the black / blue / white duotone treatment;
  `tone: 'natural'` shows the footage in its original colours.

## Admin panel

Sign in at **`/gs`** (change the address with an `ADMIN_PATH` variable) to edit everything without touching code: events (with logo and photo
uploads), organisers, the "Who I am" text, facts, numbers, services, skills, career history, map
cities, the header video, contact details, plus a visitor log, saved contact messages and
backup / restore.

- **Password.** Easiest: set `ADMIN_PASSWORD` in the host's environment variables. Otherwise, on a
  server that keeps its files, open `/gs` and choose a password on first visit — you'll be asked for
  the one-time **setup code** printed in the app's log at start-up (also saved in
  `data/setup-code.txt`), so nobody else can claim the panel first. The password is stored hashed in
  `data/admin.json`; change it under *Backup & settings*. Set `SESSION_SECRET` so sign-ins survive
  restarts.
- **Where things are saved.** Edits go to `data/content.json` (it takes precedence over
  `data/profile.js`, which stays as the built-in default); uploads go to `public/uploads/`.
  Both are git-ignored — use *Backup & settings → Download backup* regularly, and copy the uploads
  folder when moving servers. `DATA_DIR` / `UPLOAD_DIR` override the locations.
- **Vercel.** The app folder is read-only there, so the admin falls back to `/tmp`: you can try it,
  but edits disappear when the instance is recycled. Hostinger (or any server with a disk) keeps them.
- Images are shrunk in the browser before upload (photos 1800px, logos 900px; SVG kept as is).
  Uploaded logos are referenced by URL (`logoUrl`) and override the built-in `logo` slug.
- Protection: HMAC-signed cookie (7 days), 8 failed sign-ins per 10 minutes per IP, same-origin
  checks on every change, `noindex` on all admin pages.

## Show pages

`/shows/<id>` renders `views/show.ejs` for every entry in `shows`: logo, role, venue and dates, the
show image, summary and highlights, what Umit did there, his role at that organiser, newer/older
navigation and other shows for the same organiser. `/shows` redirects to the Shows section of the
home page; unknown ids return the 404 page.

## Visitor log

There is no consent banner: like a normal web server, the site records every public page view on
the server and shows the results in the admin panel (Dashboard and **Visitors**).

- Each record has: time, IP address, visitor id (a hash of IP + browser, used to count visitors rather
  than page views), browser, OS, device type, user agent, country/region/city, page, external referrer
  and browser language. Bots and crawlers are flagged, and so are your own page views (a cookie is set
  on the browser you sign in to the admin with); both are hidden by default and can be shown with a tick box.
- Location comes from the host's geo headers when present (Vercel: `x-vercel-ip-*`; Cloudflare:
  `cf-ipcountry`). Hosts without them (e.g. Hostinger) are looked up at **ipapi.co** (free tier,
  ~1,000 lookups a day; answers are cached per IP for a day). Set `GEOIP_PROVIDER=off` to turn that off.
- Records are appended to **`data/visits.jsonl`** (git-ignored, newest 20,000 kept). An older
  `data/visits.json` is migrated automatically. On Vercel the disk is temporary, so the log only lasts
  as long as the instance.
- The admin panel offers summaries (visitors per day for 30 days, countries, cities, pages, referrers,
  browsers, devices, languages), a searchable table, a CSV download and a "clear log" button.
  The raw log is also available without signing in at **`GET /api/visits?key=<ADMIN_KEY>`** once an
  `ADMIN_KEY` environment variable is set (without it the route answers 404).
- Admin pages, API calls, prefetches and failed requests are not counted.
- `/privacy` (`views/privacy.ejs`) is the privacy notice linked from the footer — keep it in step with
  what you collect and how long you keep it (it currently says up to 12 months).

## Contact form

`POST /api/contact` validates the message, ignores bots that fill the hidden honeypot field and
allows one message per visitor every 30 seconds. It then delivers the enquiry in the first way that works:

1. **Email (recommended).** Set these environment variables and every enquiry is emailed to you,
   with Reply-To set to the visitor:

   | Variable | Example (Hostinger mailbox) |
   | --- | --- |
   | `SMTP_HOST` | `smtp.hostinger.com` |
   | `SMTP_PORT` | `465` |
   | `SMTP_USER` | `hello@umitbozdag.com` |
   | `SMTP_PASS` | the mailbox password |
   | `CONTACT_TO` | optional, defaults to the email in `data/profile.js` |

2. **File.** Without SMTP settings, messages are appended to `data/messages.json` (git-ignored).
   This file is wiped on each redeploy.
3. **Visitor's email app.** If neither works (e.g. on Vercel, where the disk is read-only, or the
   mail server is down) the browser opens the visitor's email app with the message pre-filled
   to your address, so no enquiry is lost.

## Deploy on Hostinger

Needs a Hostinger plan with **Node.js Web Apps** (Business or Cloud web hosting, or a VPS).

1. hPanel → **Websites** → **Add website** → **Node.js Web App** → **Import Git repository**.
2. Connect GitHub and pick `Umo86/Umitbozdag.com`, branch `master`.
3. Build settings: framework **Express** (or "Other"), Node version **20 or 22**,
   install/build command `npm install`, entry file `server.js`, start command `npm start`.
   To self-host the header video, use `npm install && npm run fetch:video` as the build command.
4. Environment variables: `NODE_ENV=production`, the `SMTP_*` variables above so the contact form
   emails you, `ADMIN_PASSWORD` (and ideally `SESSION_SECRET`) for the admin panel, and
   (location lookups via ipapi.co are on by default; `GEOIP_PROVIDER=off` disables them). Hostinger provides `PORT` automatically.
5. Deploy, then attach `umitbozdag.com` / `www.umitbozdag.com` under the app's **Domains** and enable SSL.

Every push to the chosen branch can redeploy automatically (toggle in the app's deployment settings).

**On a Hostinger VPS instead:** `git clone` the repo, `npm install --omit=dev`, then
`NODE_ENV=production pm2 start server.js --name umit-site`, and put Nginx in front for the domain and SSL.

## Deploy elsewhere

Any Node host works. The app reads `PORT` from the environment and listens on `0.0.0.0`.

- **Vercel / Render / Railway / Fly.io**: build command `npm install`, start command `npm start`.
  Set `NODE_ENV=production` (enables `trust proxy` so rate limiting sees real client IPs).
- **VPS**: run under `pm2` or a systemd unit behind Nginx/Caddy for TLS; set `NODE_ENV=production`.
- Point the `www.umitbozdag.com` DNS at the host and enable HTTPS.

Security headers (incl. a Content-Security-Policy that only allows same-origin scripts, Google Fonts
and the Pexels media/image CDNs) are set by Helmet in `server.js`; keep scripts in `public/js/`
rather than inline. Routes: `/`, `/shows/<id>`, `/privacy`, `POST /api/contact`, `POST /api/visit`,
`GET /api/visits?key=…`, `GET /api/profile`.

## Maintenance scripts

- `npm run build:media` — re-render the illustrated London scene images (and `--video` for a looping
  fallback clip). Needs Playwright: `npm i -D playwright && npx playwright install chromium`.
- `npm run build:map` — regenerate the world-map dots (only if you change the map grid).
- `npm run fetch:video` — download the header video for self-hosting.
